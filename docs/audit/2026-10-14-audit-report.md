# GridMaster (gridmaster-react) Audit Report

Audience: maintainer. Use as the fix backlog. Paths: `v1/` means `legacy/v1/src/`. "confirmed" = an independent verifier reproduced or traced it in code; "unverified" = single reviewer, code-read only. Verifier severity overrides reviewer severity throughout. Several verifiers found "critical/high" claims overstated; severities below are the post-verification values.

## 1. Executive summary

GridMaster v1 is a readable, strictly typed, Excel-flavoured React grid (about 16k LOC, 70 src files) with a real feature spread: formulas, color filter and sort, format painter, history, fill handle, ribbon toolbar. It builds, its 7 original suites pass, and `npm audit --omit=dev` is clean. It is not state of the art. Four systemic problems dominate:

1. **Repo state.** The working tree is a half-finished restructure. `legacy/v1/` holds the working, published v1 (npm `gridmaster-react@0.2.0`) with no manifest, tsconfig or vite config. The root is a v2 scaffold (`packages/core`, `packages/react`, `apps/playground`) with config files only, no `src/`. The "accepted" v2 plans and their tests exist only in dangling git objects (tree `fae309b2e7502028bb6b30f2b4ad9abc6ef43193`, about 3k LOC), which `git gc` can prune. Root build, typecheck, CI and the legacy test runner all fail. Nothing can currently release a 0.2.1.
2. **Dead or lying API.** About 20 public props are accepted and ignored (`enableEditing`, `enableClipboard`, selection toggles, `enableValidation`, drag, conditional formatting, `onCopy`/`onPaste`). Change callbacks refire on every parent render and can loop. Inline column definitions wipe undo history. Undo/redo never tell a controlled host.
3. **Silent wrong data.** Formula engine: IFERROR never catches errors, blanks count as 0 in AVERAGE/COUNT/MIN, VLOOKUP/INDEX/MATCH misread ranges, references are never adjusted on fill/insert/delete. Paste starts at the wrong cell for extended selections. Number parsing nulls locale-formatted input. Cursor and scroll reset to A1 on any row-count change.
4. **Accessibility and packaging are the weakest dimensions.** No ARIA grid semantics, a document-level keydown handler that traps Tab and hijacks toolbar and menu keys, no keyboard route to menus. Published 0.2.0 has no license field, no `"use client"`, ESM-only types for CJS consumers, no release automation.

**Recommended path: hybrid (C).** (0) Today, anchor the dangling v2 objects with a ref. (1) Restore v1 as the shipping package and make the toolchain green around it (A-001, A-023 to A-028). (2) Fix the High and Medium defects additively in v1; this is what the project CLAUDE.md already mandates (never remove or rename props). (3) Run v2 on a `next` branch and port its good parts (core store, selectors, formula registry) behind v1's public API one plan at a time. Finish-v2-only is rejected: about 3k LOC against v1's 16k, the spec breaks every consumer, and its premise "no v1 users" is false (0.2.0 is on npm and the Stakeholder app vendors this code). Restore-v1-only is a valid fallback but leaves the 20+ `enableX` boolean architecture and the monolithic hook in place.

Note: ownership and licensing (LICENSE holder is an individual) should go to Legal/compliance before any public release (see A-111).

## 3. Baseline build/test facts

- Scratch copy of v1 (from legacy/v1 plus root configs from e2ac358): `npm ci` OK (23 packages added), `npm run build` OK (vite lib ESM+CJS, 70 modules, then `tsc -p tsconfig.build.json`, exit 0, no TS errors).
- Unmodified `legacy/v1/tests/run.mjs` fails at load with ERR_MODULE_NOT_FOUND for `tests/integration.test.mjs`. Cause is the restructure: commit 3b00f0c added the file and wired it in (8 suites), the staged tree deletes it (`D tests/integration.test.mjs`) but `run.mjs` still imports it. With the file restored in scratch only (`git show 3b00f0c:tests/integration.test.mjs`), `node tests/run.mjs` exits 0 and prints `passed 8 test suites`. The 7 original suites pass; CLAUDE.md's "7" is stale. The integration suite only calls `React.createElement` and asserts on props (A-100).
- Root (v2 scaffold) commands: `typecheck` fails TS18003; `build` fails in all 3 workspaces (no entry); `format:check` fails (15 errors locally); `lint` passes only because biome ignores `legacy/`; `test:unit` passes with one vacuous test; `npm ci` with strict peers fails ERESOLVE in the working tree.
- Bundle (v1): `dist/index.js` 216.9 KB raw / 52.2 KB gzip; `dist/index.cjs` 159.1 KB raw / 44.6 KB gzip; `styles.css` 15.2 KB raw / 3.3 KB gzip. Sourcemaps about 665 KB each. Packaging reviewer verified react, react-dom and lucide-react are externalised; the 58 KB ESM-vs-CJS gap is unexplained (not checked further).
- Type hygiene: 39 `any` in src (concentrated in core/types.ts, editing.ts, fill.ts, structure.ts, utils.ts), 0 `@ts-ignore`/`@ts-expect-error`/eslint-disable, no test files in src. Tests are 819 lines (7 `.mjs` suites) for about 16k LOC, none touch the React layer.
- `npm audit --omit=dev`: 0 vulnerabilities. Full audit: 4 high, all dev/build-time (postcss, source-map-js, vite 8.0.0-8.0.15, launch-editor); `npm audit fix` available (A-107).
- Tests, CRLF note: working tree is CRLF, so naive byte diffs against git show differ on every file.
- Not run: `build:demo`, test-app build.
- Secrets scan: no credentials in tracked or untracked files.
